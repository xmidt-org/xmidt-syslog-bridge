# Retry what can succeed later, drop what never can

A write to the **Syslog Destination** fails for two reasons that need opposite handling. Transient failures — rsyslog restarted and the socket is stale (`ECONNREFUSED`), or its queue is full (`EAGAIN`) — succeed once the condition clears, so we retry with backoff and never commit the offset, which is ADR 0001 working as intended. A permanent failure — the datagram exceeds the socket buffer (`EMSGSIZE`) — will never succeed no matter how long we wait, so we drop the message, count it, log at error with partition, offset and size, and commit. Retrying a permanent failure forever would let one oversized message block its partition indefinitely and stall every device behind it, which is a far worse outcome than losing that one message. This is the only case in which xmidt-syslog-bridge knowingly discards a deliverable **Syslog Message**, and it is deliberately loud.

xmidt-syslog-bridge never truncates. It writes the **Syslog Message** bytes in full and lets rsyslog apply its own `global(maxMessageSize)` limit, which defaults to 8 KB and silently chops anything longer. We cannot observe that from our side, so it is a deployment concern: operators must raise `maxMessageSize` to cover the largest expected alert. Truncating on our side instead was considered and rejected because it would put a byte-preservation exception into the one component whose entire purpose is byte preservation, while still losing the same bytes.
